# THE SEED Governance — Initial Proposal

This document is a proposal, not an adopted legal governance constitution.

## Seed Enhancement Proposals (SEPs)

Protocol, identity, crypto, consensus, transfer-authority, patch-policy, compatibility, and character-continuity changes should be introduced through public SEPs.

Each SEP should state:
- Identifier and status.
- Problem and motivation.
- Proposed design and alternatives.
- Compatibility impact.
- Security, privacy, character-continuity, and player-consent analysis.
- Creator-rights, asset-license, and provenance impact where applicable.
- Migration/activation plan.
- Test vectors and reference implementation.
- Reviewers and decision record.

## Change classes

- Editorial/documentation: normal pull request review.
- Non-critical implementation: code owner review and tests.
- Protocol/schema: compatibility review and SEP when public behavior changes.
- Security/identity/cryptography/transfer authority: security review plus relevant maintainers.
- Consensus/governance/global release trust: explicit high-assurance process; no AI self-approval.

## Character continuity governance

Changes to Character Identity Anchors, Continuity Manifests, transfer previews, memory/AI context, or archival behavior must be reviewed against `docs/CHARACTER_PHILOSOPHY.md`. The player’s emotional bond with a character is a product value, not an excuse to bypass privacy or creator rights. No governance process may treat player-authored private continuity as public network property.

## Independence goals

Governance should gradually distribute maintenance, release, review, and validator operations among independent participants. Running multiple nodes under one operator does not provide organizational decentralization.
